# Auto Review Hub — Deployment

This application has four runtime pieces: the Django app (which also serves
the built React frontend), the Express service, MongoDB, and the Flask
sentiment analyzer. Any real deployment must run all of them. GitHub Pages
is not one of the options: it hosts static files only, with no Python, no
Node, and no database, so the app cannot function there. The earlier Pages
workflows have been removed from this repository.

## Option 1: Render (free tier) — included Blueprint

The repo ships `render.yaml`, which creates three free Docker web services:

| Service | Source | Purpose |
|---|---|---|
| `auto-review-hub` | `server/Dockerfile` (multi-stage: builds React, then Django) | The public app |
| `auto-review-hub-api` | `server/database/Dockerfile` | Express dealers/reviews API |
| `auto-review-hub-sentiment` | `server/djangoapp/microservices/Dockerfile` | Sentiment analyzer |

MongoDB runs on MongoDB Atlas (free M0 cluster), which Render services
connect to through the `MONGO_URL` environment variable.

### Steps

1. **MongoDB Atlas**: create a free M0 cluster. In Atlas, add a database
   user, then under Network Access allow `0.0.0.0/0` (demo setting). Copy
   the connection string (it looks like
   `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/`).
2. **Render**: New → Blueprint → select this repository. Render reads
   `render.yaml`.
3. When prompted for the unsynced variables, fill in:
   - `MONGO_URL` — the Atlas connection string from step 1
   - `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_EMAIL`,
     `DJANGO_SUPERUSER_PASSWORD` — your Django Admin login (created
     automatically on first start)
4. Apply. The first builds take a few minutes (the Django image also builds
   the React frontend).
5. Open the `auto-review-hub` service URL. Register a user, open a dealer,
   post a review: it should appear in the dealer's list with a sentiment
   icon.

### Notes and limits

- Free services sleep after about 15 minutes idle; the first request after
  that takes 30–60 seconds.
- The Django service name determines its URL (`auto-review-hub.onrender.com`).
  If a name is taken, Render adjusts the URL: then update `backend_url` and
  `sentiment_analyzer_url` in the `auto-review-hub` service's Environment
  tab to the actual API and sentiment URLs and redeploy that one service.
- Django's SQLite file lives on the service's ephemeral filesystem, so
  registered users reset on redeploy or restart. Dealerships and reviews are
  safe: they live in Atlas, and the Express service re-seeds its seed data
  on start. Car makes/models re-seed on demand.

## Option 2: Docker (self-hosted)

```bash
# MongoDB + Express
cd server/database && docker compose up -d

# Sentiment analyzer
docker build -t auto-review-sentiment server/djangoapp/microservices
docker run -p 5050:5050 -e PORT=5050 auto-review-sentiment

# Django app (builds the frontend inside the image)
docker build -t auto-review-hub server
docker run -p 8000:8000 \
  -e DJANGO_DEBUG=False \
  -e DJANGO_SECRET_KEY=<long-random-string> \
  -e DJANGO_ALLOWED_HOSTS=<your-host> \
  -e backend_url=http://host.docker.internal:3030 \
  -e sentiment_analyzer_url=http://host.docker.internal:5050/ \
  auto-review-hub
```

## Option 3: IBM Cloud (course deployment)

- **Sentiment analyzer → IBM Code Engine**: deploy
  `server/djangoapp/microservices` (its Dockerfile is the build source).
  Put the resulting public URL in Django's `sentiment_analyzer_url`.
- **Django app → Kubernetes**: build and push the `server/Dockerfile`
  image to your container registry, update the image name in
  `server/deployment.yaml`, then:
  ```bash
  kubectl apply -f server/deployment.yaml -f server/service.yaml
  ```
  Create the secret the deployment expects first:
  ```bash
  kubectl create secret generic auto-review-hub-secrets \
    --from-literal=django-secret-key=<long-random-string>
  ```
- **Express + MongoDB**: run with `server/database/docker-compose.yml` (or
  any hosted MongoDB) and point Django's `backend_url` at it.

## Environment variables (Django service)

| Variable | Required | Notes |
|---|---|---|
| `DJANGO_SECRET_KEY` | production | Auto-generated by the Render Blueprint |
| `DJANGO_DEBUG` | production | Set `False` |
| `DJANGO_ALLOWED_HOSTS` | production | Comma-separated hostnames, no scheme. `.onrender.com` allows all Render subdomains |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | production | Comma-separated origins, e.g. `https://*.onrender.com` |
| `backend_url` | yes | Express service base URL, no trailing slash |
| `sentiment_analyzer_url` | yes | Sentiment service base URL, with trailing slash |
| `DJANGO_SUPERUSER_USERNAME` / `_EMAIL` / `_PASSWORD` | optional | If set, entrypoint creates that admin user on start |
| `MONGO_URL` | Express only | MongoDB connection string; defaults to the Docker Compose host name |
